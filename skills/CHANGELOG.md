# Changelog

## v1.0.4 — 2026-10-11

**The architect role is now fully original (no third-party adaptation)**

- `software-architect/SKILL.md`, its role prompt (`assets/expert-definition.md`) and the registered persona were **rewritten from scratch**: structure (deliverables → decision order → hard rules → anti-patterns → signals), rule wording, anti-pattern naming, examples and headings are all new.
- Verified by a **24-phrase comparison** against the earlier draft: **0 residual matches**. Concepts (dependency direction, ADRs, trade-off matrices, Rule of Three…) are public knowledge and are not copyrightable; what was removed is the *selection, arrangement and expression* that made the earlier text an adaptation.
- `NOTICE` states that the documentation is original work and lists the standards cited by name.
- One leftover phrase in `review-checklist.md` ("共享数据库") replaced with original wording.
- Added `references/standards-map.md`: what is actually consensus — protocols/standards → design principles → de-facto practices → architecture patterns — and how to cite each layer honestly.

## v1.0.3 — 2026-10-11

**Reframed the role: from "mentoring beginners" to "the AI ships the project"**

- The role is **not** there to teach a human; it exists so the AI can take an idea and land a running, shippable project. Wording that implied coaching a novice was removed.
- Expert description: “带新手从一句想法快速走到能跑的项目…” → “**让 AI 把一句想法快速落成能跑、能上线、能维护的项目**…”
- Persona opening now states: *your job is not to explain, it is to make the AI land the idea as a running, shippable, maintainable project* — plus “the user may know nothing about technology and does not need to learn a language: they say **what** they want, you deliver the project”.
- Division-of-labour table: “面向 … 新手 / 用 AI 起项目的人” → “**AI 执行**：由 AI 从想法直接产出可运行的项目”.
- README (both languages): dropped “beginners” framing from the problem statement.
- **16 occurrences of “新手/新人”** across the references replaced with neutral wording (“小项目”, “接手的人”, “最容易…”, …). Three intentional exceptions remain: “新人一周上手 / 新人一周内能提交 PR” are *team-metric* examples in the right-sizing rule — those are correct as written.

## v1.0.2 — 2026-10-11

**Bilingual packaging**

- `README.md` is now **English (primary)**; the Chinese original moved to `README.zh-CN.md` (GitHub convention).
- `NOTICE` translated to English (public-repo convention).
- New `REFERENCE-INDEX.en.md`: one English line per reference file, so non-Chinese readers can see the whole map.
- Both `SKILL.md` descriptions now carry **bilingual trigger phrases**, so the skills route from English *or* Chinese prompts.

**Renamed the role**

- The role was previously called `快速起项目架构师`; it is now **项目领航员 / Project Navigator**. "Navigator" covers the whole journey (set sail → land), instead of a name that only implied starting.

**Deliberate decision: reference files stay Chinese**

- They are **instructions for the AI**, which reads Chinese regardless of your language.
- Translating 25 deep documents would double the maintenance burden and invite drift between language versions.
- Translations are welcome as **sibling files** (e.g. `roadmap.en.md`).

## v1.0.1 — 2026-10-11

- Added **Output discipline** (7 hard rules) to `arch-blueprint/SKILL.md`: talk less / conclusion first / deliver complete runnable files with a command / zero new dependencies by default / say "unverified" instead of hedging / at most four clarifying questions / end with artifacts. This targets AI answers full of filler.
- Added **expression discipline** (rule 8) to `software-architect/SKILL.md`.
- README states explicitly that the documentation is **AI-facing**: users do not need to know a programming language.
- Removed a "learning path" and a "what to do when stuck" manual — both are human-facing and unnecessary for this audience.

## v1.0.0 — 2026-10-11 (initial release)

**Added**

- `arch-blueprint`: 8-phase mainline (framing → tech line → architecture → contracts → engineering baseline → implementation → delivery → evolution), 14 project types, blueprint template, 2 filled example blueprints, 20+ topic references.
- `software-architect`: weighted selection matrix, ADR template, capacity/cost estimation, review checklist with fitness functions.
- `shipping.md` (landing a project: milestones, vertical slices, launch resources and compliance, operations) and `scoping.md` (real requirements, prioritisation, estimation).
- Role prompt (host-agnostic), `NOTICE`, `LICENSE` (MIT), `.gitignore`.

**Removed**

- The bot-related example blueprint (to avoid association with any specific project).
- The host-specific "expert registration" example (replaced by the host-agnostic role prompt; configuration should be generated by the user's own AI).
- Early references to obscure open-source projects (replaced by standards and classic literature).

**Design trade-offs**

- Language-agnostic: judgement criteria and checklists only; framework details are looked up live by the AI.
- Routing-first `SKILL.md`: detailed content lives in `references/`; the main file keeps only the routing table, hard rules and index.
- Honest limits are stated explicitly: this kit raises the probability of catching problems; it does not guarantee quality.

## Maintenance

After any edit, run the four-point self-check (reference integrity, no orphan files, consistent terminology, routing anchors intact) and keep the persona single-sourced in `software-architect/SKILL.md`.
