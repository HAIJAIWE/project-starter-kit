# 起项目方法论技能包（AI 起项目 / 架构图纸）

> **English version: [README.md](README.md)** ｜ 每个参考文件的英文一句话索引见 [REFERENCE-INDEX.en.md](REFERENCE-INDEX.en.md)

给"用 AI 从零起项目"的人用的一套方法论文档：**两个技能 + 一份角色提示词**。

> **这套文档是给 AI 读的**：你只要把想法说清楚（它要做什么、给谁用、跑在哪），清单、结构和代码交给 AI 执行——**你不需要懂编程语言**。
> 反过来，文档里对 AI 有一条硬性纪律：**少说多做**——直接给能跑的文件与命令，不写方法论演讲、不复述清单、不写"总结 / 展望"这类填充段落。

它有两种用法：**起项目**（从一句想法走到能跑、能上线）和 **看项目**（给已有项目做体检）。

---

## 这套东西解决什么问题

用 AI 起项目的典型死法，通常不是"不会写代码"，而是：

1. **不知道先做什么** —— 一上来就想把整个产品写完，然后卡住；
2. **目录和分层没有标准** —— 越写越乱，改一个功能要动五个地方；
3. **AI 说"已完成"，但没人真的跑过** —— 交付的是"看起来对"的代码；
4. **技术选型靠"教程用什么我就用什么"** —— 选完发现换不掉。

这套文档把这四件事变成**可执行的清单 + 出口标准 + 验收方法**。

## 怎么用

### 1. 作为技能安装

把 `arch-blueprint/` 与 `software-architect/` 两个目录放进你的技能目录（DSH / Claude 的 `skills` 目录），**新开会话**即可被加载。
（只装一个也能用：`arch-blueprint` 的评审部分自带 `references/acceptance.md` 评分表；`software-architect` 的评审部分自带 `references/review-checklist.md`。）
技能靠 `description` 里的触发条件自动路由，例如："我有个想法想做 X""帮我起架构""该用什么技术栈""帮我看看这个项目有什么问题""项目太乱了想重构"。

### 2. 把角色提示词用起来（可选，任何宿主都能用）

打开 `software-architect/assets/expert-definition.md`，把**第二节那段提示词**交给你的 AI，让它按你的环境生成配置：

> 「把这段提示词做成我环境里的一个角色（自定义专家 / agent preset / system prompt 都行）：<粘贴>。名称用『项目领航员』，分组用『工程』。不要引入我没有的插件，也不要照抄别人机器上的路径。」

**本仓库不含任何机器相关的配置文件**——路径和插件因环境而异，让 AI 按你的环境生成，或者只用技能名指代。

### 3. 典型用法

| 场景 | 怎么说 |
|---|---|
| 起项目（从 0 到能跑） | 「用 arch-blueprint 帮我把这个想法拆成图纸」 |
| **看项目（给已有项目做体检）** | 「按 arch-blueprint 的评审路径 + software-architect 的评审清单，给这个项目做体检，**只报告不修改**」 |
| 技术选型 | 「用 software-architect 做选型，至少给两个方案 + 权衡矩阵」 |
| 交付前评审（多视角） | 「按 `arch-blueprint/references/team-brief.md` 组一个专家团，独立评审后交叉核验」 |

## 实测结论（诚实版）

我们用这套东西对一份真实的 Electron + TypeScript 项目做过一次 A/B 对照（同一批冻结文件，两组互相隔离）：

- **单人组**（技能 + 角色）在 846 行代码里给出 **10 条可定位风险**，格式统一（位置 / 为什么算问题 / 最小修法），且**没有越级建议**；
- **三人专家团**在同一材料上给出 18 条（去重后），其中 **8 条是单人没发现的**（含 2 条高危）；
- 那份代码当时 `eslint` 干净、**149 个测试全绿**，**依然查出 3 个阻断级问题**——其中一处会让读取时**删掉用户数据行**。

**结论：这套东西提高的是"发现问题"和"不跳步"的概率，不保证生成高质量项目。**
项目质量最终取决于：需求是否真实、有没有真的验证过、以及有没有人持续维护。

## 维护与自检

改动本仓库后，逐条核对这四项（不需要脚本）：

1. **引用完整性**：`SKILL.md` 里提到的每个 `references/...`、`assets/...` 路径都真实存在；
2. **无孤儿文件**：每个 reference / asset 文件都在对应 `SKILL.md` 里被提到，否则 AI 找不到它；
3. **术语一致**：同一概念只用一种叫法（例如统一叫"代码质量门"）；
4. **关键锚点还在**：八阶段表、铁律、参考文件索引——这三样是**路由能力的骨架**，缺了技能就会"知道但找不到"。

**人格提示词只维护一份**：以 `software-architect/SKILL.md` 为准，`assets/expert-definition.md` 第二节同步。

变更历史见 `CHANGELOG.md`。

## 发布前请检查

如果你是从一个**真实项目仓库**里整理出这套技能的，注意别把这些一起发出去（`.gitignore` 已给排除示例）：

- 项目内部的评审 / 审计报告
- **未修复漏洞清单**（等于公开自己的漏洞）
- 你本机的客户端 / 插件配置文件（含绝对路径）
- 任何凭据、`.env`、密钥文件
