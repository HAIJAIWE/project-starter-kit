### 用这张表的纪律（比表本身重要）

1. **权重必须来自硬约束**，不能来自偏好。预算是硬约束，权重就给高；"我喜欢"不是权重。
2. **打分是主观的**：它的价值在于**把分歧摆到桌面上**（"你为什么给它 9 分？"），不在于算出的那个数。
3. **先做否决**：不满足硬约束的候选直接删，别放进表里陪跑（否则会出现"高分但不可用"的荒谬结论）。
4. **差距小于 1 分时选可逆的那个**（单向门除外，那时要按"能不能承受错误"来选）。
5. 表要进 ADR，并写清"如果哪一列判断错了，结论会翻转"。

## 二、容量与成本估算

### 2.1 公式（语言无关）

| 量 | 公式 | 说明 |
|---|---|---|
| 日请求量 | `DAU × 人均操作数` | DAU = 日活用户数 |
| 平均 QPS | `日请求量 ÷ 86400` | 全天平均 |
| **峰值 QPS** | `平均 QPS × 峰值倍数` | **倍数由流量分布决定，不要拍脑袋** |
| 存储/年 | `日请求量 × 单条字节数 × 365 ÷ 1024³` (GB) | 单条字节数要按真实字段估算 |
| 带宽 | `峰值 QPS × 单次响应字节数 × 8` (bps) | 注意是比特不是字节 |
| 成本/月 | 各资源单价 × 用量（计算 + 存储 + 出流量 + 第三方调用） | AI 项目把**模型调用**单列 |

### 2.2 峰值倍数怎么定（**原提示词这里自相矛盾**）

常见两种说法要分开：
- "峰值是平均的 3 倍" → `峰值 QPS = 平均 × 3`
- "60% 的流量集中在 4 小时内" → `峰值 QPS ≈ 日请求量 × 0.6 ÷ (4×3600)`

**这两个假设不能同时写**（一个说 3 倍，一个推出的倍数完全不同）。正确做法是**只选一种并写明来源**：
- 有历史数据 → 用真实分时曲线取 P95；
- 没有数据 → 用"高峰时段占比法"（更直观），并标注"假设"。

### 2.3 算例（照这个格式写）

> **假设**：DAU 50 万、人均 20 次操作、单条记录 2 KB、高峰 4 小时内承载 60% 流量、响应体 10 KB。
> - 日请求量 = 500,000 × 20 = **10,000,000**
> - 平均 QPS = 10,000,000 ÷ 86,400 ≈ **116**
> - 峰值 QPS = 10,000,000 × 0.6 ÷ 14,400 ≈ **417**
> - 年存储 = 10,000,000 × 2,048 × 365 ÷ 1,073,741,824 ≈ **6.8 TB/年**
> - 峰值带宽 = 417 × 10 KB × 8 ≈ **33 Mbps**
> - **结论**：单库单机扛不住 417 QPS 的写放大时再加缓存/读写分离；存储 6.8 TB/年 → 一年内必须定归档或冷热分层策略。

**纪律**：每个假设单独列一行；不要给"大概很快"这种结论；结论要落成"什么时候该做什么"。

### 2.4 成本失控点自查（小项目最常炸的地方）

- [ ] 大模型调用：有没有每用户/每日配额、预算上限、降级到便宜模型？
- [ ] 短信/推送/支付回调：单次费用 × 潜在滥用频率？
- [ ] 对象存储出流量：被热门外链刷过吗？
- [ ] 日志与监控：按量计费时，日志量会不会自己把自己读穷？
- [ ] 定时任务频率：有没有"每分钟跑一次全量"的写法？

## 四、边界（子系统/服务）评估表

| 判据 | 是/否 | 说明 |
|---|---|---|
| 能单独替换？ | | 换实现不影响调用方 |
| 能单独测试？ | | 有独立测试入口 |
| 能单独部署/重启？ | | 重启它不中断其他部分 |
| 数据写权限唯一？ | | 一张表只有一个写入方 |
| 职责能一句话说清？ | | 说不清就是边界没找对 |
| 有一致的业务术语？ | | 同一个词在别处含义相同 |

**判断法则**：
- 前三条都"是" → 是合格的子系统/服务边界。
- 只有第一条"是" → 它只是模块，不是子系统（不要拆成服务）。
- 第 4 条为"否" → **边界是假的**（要么合并，要么收回写权限）。
