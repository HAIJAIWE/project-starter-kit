# 样板图纸 3：命令行小工具（玩具级 · 展示"缩范围不降标准"）

> 填满的实例，规模最小。重点看：**五层怎么压扁**、**退出码也是接口**、以及**规模变小到底省了什么、没省什么**。
> 规模：玩具 / 脚本级。类型：CLI 工具。

---

## 阶段 0 · 立项与边界

- **给谁用**：我自己，偶尔给同事用。
- **完成什么动作**：把一个每月重复的手工动作变成一条命令（读一个目录下的记录文件，输出统计结果）。
- **从哪用**：命令行；可能被别的脚本调用。
- **数据**：读本地文件，输出到屏幕（可以重定向）。不联网。
- **外部**：无。
- **跑在哪 / 谁维护**：自己电脑；我自己。

### 关键场景
| # | 场景 | 这次做吗 |
|---|---|---|
| 1 | `tool stats ./data` → 打印统计表格 | **做（MVP）** |
| 2 | `tool stats ./data --json` → 输出 JSON 给脚本用 | 做（第二条） |
| 3 | 定时自动跑并发邮件 | 以后再说 |

### 不做清单
不做配置系统、不做插件机制、不做 GUI、不做多语言、不做守护进程。

---

## 阶段 1 · 技术线

### 硬约束
| 约束 | 内容 | 影响 |
|---|---|---|
| 人力 | 我自己写、自己用 | 选我最熟的语言，不追新 |
| 依赖 | 别人电脑上要能直接跑 | 尽量只用标准库 + 一个参数解析库 |
| 输出 | 可能被脚本消费 | **输出格式与退出码必须稳定** |
| 平台 | Windows 与 macOS 都要能用 | 路径处理用标准库，不写死分隔符 |

### 单向门 vs 双向门
| 决策 | 类型 | 决定 |
|---|---|---|
| 输出格式（含 `--json` 字段名） | **单向门**（别人脚本会依赖） | 定下来，写进 README，只加不改 |
| 退出码约定 | **单向门** | 0 成功 / 1 用法错 / 2 运行错 |
| 语言 | 单向门（重写成本高） | 用我最熟的 |
| 参数解析库 | 双向门 | 用主流库，或用标准库 |
| 日志与格式化 | 双向门 | 快决定 |

### 限时原型
不需要（不确定性低）。唯一先验证的一点：**大文件会不会吃爆内存** → 改成逐行流式处理。

---

## 阶段 2 · 架构（五层压扁）

| 层 | 这个项目里是什么 |
|---|---|
| **系统** | 这个 CLI 本身（有入口、能跑、能给结果） |
| **子系统** | 只有 1 个 → **不建目录**（层是思考方式，不是目录要求） |
| **模块** | 三类函数：参数解析 / 核心统计 / 输出格式化（同一文件内分区即可） |
| **组件** | 单个函数：`parseArgs`、`loadRecords`、`summarize`、`renderTable`、`renderJson` |
| **接口** | 函数签名 + **进程级契约（参数 / stdout / stderr / 退出码）** |

依赖方向：入口 → 参数解析 → 核心统计 → 输出；**核心统计不依赖输出格式**（所以 `--json` 是加一个渲染器，不动业务）。这一条就是"接口先行"在小项目里的样子。

### 候选拆法对比
| 方案 | 优点 | 代价 | 选它吗 |
|---|---|---|---|
| A 全写在一个函数里 | 最快 | 加 `--json` 就得改核心逻辑 | 否 |
| B 核心统计与输出分离 | 加输出格式不动业务；核心能单测 | 多花 20 分钟 | **是** |

### 数据模型
无数据库。输入文件格式：每行一条记录（字段分隔明确、UTF-8）。**格式约定写进 README**，并在读取时对格式错误给出带行号的提示。

### 质量属性（数字）
| 属性 | 要求 | 架构后果 |
|---|---|---|
| 性能 | 10 万行文件 3 秒内 | 流式读取，不整体载入 |
| 可用性 | 崩了就重跑（无状态） | 不需要守护与告警 |
| 隐私 | 数据只在本机处理，不上传 | 无网络调用 |
| 成本 | 0 | 无外部依赖 |
| 可维护 | 半年后我还改得动 | 单文件 + 分区注释 + README 示例 |

### 部署形态
本地可执行；发布 = 打标签 + 在 README 写清安装方式（或复制脚本）。回滚 = 保留上一版文件。

## 阶段 3 · 契约（小项目最容易被忽视的一环）

| 契约 | 内容 |
|---|---|
| 参数 | `tool stats <dir> [--json] [--top N]`；未知参数 → 打印用法 + **退出码 1** |
| stdout | 只放数据（表格或 JSON）。**别混入日志**，否则管道消费会坏 |
| stderr | 放日志与错误信息 |
| 退出码 | 0 成功；1 用法错；2 运行错（文件不存在、格式错） |
| 错误信息 | 带文件与行号；不打印堆栈给普通使用 |
| `--json` 输出 | 字段名稳定、只加不改；数字不加千分位、金额用整数分 |

**假实现**：`summarize` 先返回固定数字，把参数解析与两种渲染先跑通。

## 阶段 4 · 工程化（缩范围，不降标准）

| 项 | 这个项目怎么做 |
|---|---|
| 版本控制 | git；`.gitignore` 排除本地数据文件与输出 |
| 密钥分离 | 无密钥（**这一点要在 README 写明**，避免以后有人加 key 时随手硬编码） |
| README | 三段：装、用法示例（含 `--json` 与退出码）、输入文件格式 |
| 可回滚 | 保留上一版可执行文件；标签管理版本 |
| 测试 | 核心统计 3–5 条（含边界：空文件、单行、格式错行） |
| 依赖锁定 | 若用了第三方库则锁版本；**优先零依赖** |
| 日志 | 出错走 stderr；不用日志框架 |
| CI | 可选；跑一次测试即可 |

**省掉的是**：迁移脚本、备份、告警、环境分离、限流——因为没有这些风险。
**没省的是**：契约、错误语义、README、可回滚、一条真测试。这就是"缩范围不降标准"。

---

## 阶段 5 · 实现顺序

1. `parseArgs` + 用法输出与退出码 → 2. `loadRecords`（流式 + 行号报错）→ 3. `summarize`（假数据先行）→ 4. `renderTable` → 5. `renderJson` → 6. 边界测试（空文件、格式错、超大文件）。

---

## 阶段 6 · 交付

- README 里的示例**必须真的跑过一遍**（照抄 README 能跑，才算交付）。
- 版本号 + CHANGELOG（很短，但要有）。
- 在 Windows 与 macOS 各跑一次（跨平台是这类工具最容易漏的）。

---

## 阶段 7 · 演进

| 升级 | 触发信号 |
|---|---|
| 拆目录 / 多文件 | 单文件超过约 500 行，或出现第二个子命令 |
| 加子命令体系 | 出现第二类操作（不只是 `stats`） |
| 做成库（可被 import） | 别人要在代码里调用而不只是命令行 |
| 加配置系统 | 默认值不够用（**先确认不是需求搞错了**） |
| 加国际化 | 有非中文使用者（见 `i18n-and-a11y.md`） |
| 定时自动跑 | 有人真的每天手动跑（→ 那可能该做成服务，而不是给 CLI 加定时） |

---

## 现在不做什么

| 排除 | 为什么 | 什么信号出现才做 |
|---|---|---|
| 配置系统 | 默认值够用，配置是复杂度 | 默认值真的不够 |
| 插件机制 | 只有我一个人用 | 有第三方要扩展 |
| GUI | 命令行够用 | 有非技术用户要用 |
| 多语言 | 只有中文使用者 | 出现外语使用者 |
| 打包成安装包 | 复制脚本就能用 | 有非技术用户安装 |
| 并发处理 | 10 万行 3 秒已达标 | 文件大到单机处理不动 |
