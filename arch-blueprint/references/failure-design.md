# 失败设计（错误处理、超时、重试、幂等、并发）

**核心观念：先设计失败，再设计成功。** 正常路径只有一条，失败路径有几十条，而线上时间几乎全花在失败路径上。
小项目最常见的死法不是"功能没写完"，而是"第三方一超时就整个卡死"。

---

## 一、错误分类（分类决定处理方式）

| 类别 | 例子 | 给用户看 | 处理方式 |
|---|---|---|---|
| **用户错误** | 填错、没权限、参数缺 | 人话 + 怎么改 | 直接返回，不重试，不记 error 级日志 |
| **系统错误** | 代码 bug、数据不一致 | "我们出问题了，稍后再试" | 记详细日志 + 告警，**不重试**（重试也是错） |
| **第三方错误** | 超时、限流、5xx | 视情况（重试/降级） | 分**可重试**（超时、429、5xx）与**不可重试**（400、鉴权失败） |
| **环境错误** | 连不上库、磁盘满、密钥失效 | 同上 | 告警 + 快速失败，别拖 |

**三种错误不能混成一个"出错了"**：混了就没法决定重试、没法排查、也没法给用户有用的提示。

## 二、错误传播

- **别吞异常**：捕获了就必须处理（记录/转换/重试），空 catch 是最贵的 bug。
- 别用异常做流程控制（正常分支不该抛异常）。
- 保留上下文：谁在做什么、关键参数摘要（**绝不含密钥/令牌/密码**）。
- 错误信息分两层：**用户可见**（人话、不含内部细节）、**日志可见**（含定位所需信息）。
- 不用堆栈吓用户，但也别把真实原因藏到查不出来。

## 三、超时（最常被漏掉的一条）

- **所有跨进程调用都必须显式设超时**：HTTP、数据库、队列、外部 SDK。默认值常常是"无限等"。
- 超时要能**真的中断**（不是等它返回再忽略）。
- 分层的超时预算：总请求 3 秒 → 内部各调用加起来不能超过它，别让内层超时比外层还长。
- 慢不等于失败，但**没有超时就等于没有失败处理**。

## 四、重试

- **只重试幂等 + 瞬时错误**；重试写操作前先确认幂等。
- 指数退避 + 抖动（避免同时重试打爆对方），设最大次数与总时限。
- 重试会放大流量：对方限流时重试更糟（先看 429 的 Retry-After）。
- **用户手动重试也要防**：双击提交、刷新页面都会重复。

## 五、幂等（重复投递是常态，不是异常）

| 场景 | 会重复的原因 |
|---|---|
| 支付/下单 | 用户双击、网络重试、超时后对方其实成功了 |
| Webhook | 对方保证"至少一次"投递 |
| 消息队列 | 至少一次语义 |
| 定时任务 | 上次超时被杀，又跑了一遍 |

**做法**：给写操作一个幂等键（订单号/请求 ID），服务端记住处理结果；重复请求返回同一结果，而不是再做一次。

## 六、降级与熔断

- 想清"这个依赖挂了，用户看到什么"：用缓存值、排队稍后重试、给人工通道、明确报"暂不可用"。
- **别让一个慢依赖拖死整个服务**：设熔断/快速失败（连续失败就暂时不再调用）。
- 降级要有记录：至少让人知道"现在是降级状态"。

## 七、部分失败

- 批量操作要明确：成功几个、失败几个、失败原因、能不能重跑失败的。
- **别假装全成功**（"操作完成"但一半没写进去，是最难查的 bug）。

## 八、并发与事务边界

- 动手前先问：**"两个人同时做这件事会怎样？"**
- 共享状态要串行化：队列、锁、乐观锁（版本号）、数据库行锁。
- **事务边界放在业务层**，别跨网络调用开事务（会很慢，且容易死锁）。
- 长事务要拆：先落状态，再异步做副作用。
- 竞态的表现往往是"偶发"：偶发的 bug 优先怀疑并发。

## 九、资源释放

- 连接、文件、锁、临时文件：**失败路径也要释放**（try/finally 或语言的等价结构）。
- 连接池要设上限，别无限建连接（一个泄漏就能拖死服务）。
- 后台任务要有"卡死"保护：单任务超时上限。

## 十、失败必须可发现

- 日志（含上下文）+ 指标（失败次数）+ 告警（无人值守时必须有）。
- 静默失败是最危险的一类：**"什么都好"和"什么都没跑"看起来一样**。定时任务、爬虫、对接方改版都属高发区。

## 十一、交付前失败设计自查

- [ ] 所有跨进程调用都有超时？
- [ ] 只有幂等操作被重试？退避与次数上限？
- [ ] 关键写操作有幂等键？
- [ ] 空 catch / 吞异常的地方都清掉了？
- [ ] 用户错误与系统错误分开了吗（是否都能给人话）？
- [ ] 依赖挂掉时会怎样？有降级或快速失败？
- [ ] 并发改同一条数据会怎样？
- [ ] 失败路径有日志，且日志里没有密钥/隐私？
- [ ] 无人值守的任务失败时，有人会被通知吗？
