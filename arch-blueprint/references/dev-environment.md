# 开发环境标准化（换台电脑、换个人、半年后，一条命令能跑起来）

**目标一句话：把仓库 clone 到一个干净目录，按 README 做，就能跑起来。**
这是"可复现"的最低标准，也是项目最常翻车的地方（"在我电脑上能跑"）。

---

## 一、必备六项

| # | 项 | 最小做法 | 不做的代价 |
|---|---|---|---|
| 1 | **运行时版本锁定** | 在仓库里声明语言/运行时版本（各语言都有自己的版本文件习惯，如 `.nvmrc` / `.tool-versions` / `global.json` 一类），README 写明 | 换机器版本不符 → 各种莫名其妙的错 |
| 2 | **依赖锁定** | 保留锁文件，只从官方源装 | 今天能跑明天不能跑 |
| 3 | **配置模板** | 仓库只放 `.env.example`（键名 + 说明 + 假值）；真值不进仓库 | 要么缺变量跑到一半崩，要么把密钥传出去 |
| 4 | **启动时校验配置** | 启动就检查必需变量是否存在/格式对不对，**缺失就立刻报错并说明缺哪个** | 运行半小时后才在某个分支崩掉 |
| 5 | **一条命令启动** | 把常用动作写成脚本（启动 / 测试 / 迁移 / 构建），README 直接引用这条命令 | 命令靠口口相传，接手的人（和半年后的你）拼不出来 |
| 6 | **编辑器与风格配置进仓库** | formatter / linter / 行尾符与编码配置（如 `.editorconfig`）一并提交 | 每个人格式不同，diff 全是噪音 |

## 二、本地数据与状态

- **开发数据库怎么起**：优先嵌入式/容器化的本地实例；提供**种子数据脚本**，让接手的人一启动就能看到有内容的列表页。
- **别让开发环境连生产库**（这是最危险的偷懒）。三套配置：本地 / 测试 / 生产，互不串。
- **迁移脚本**是环境可复现的一部分：新环境靠它建结构，不能靠"我手动建过表"。
- **清理脚本**：能一键把本地数据恢复到干净状态（测试才可重复）。

## 三、密钥在开发环境怎么处理

- 用**测试模式/沙箱凭据**（第三方通常提供），不用生产密钥。
- 生产密钥**永不复制到本地**、永不写进 `.env.example`、永不贴进聊天与截图。
- 本地假密钥也要能启动（开发时允许"无外部依赖模式"），否则接手的人第一关就卡住。

## 四、容器化开发环境（可选，别默认上）

| 什么时候值得 | 什么时候不值得 |
|---|---|
| 系统依赖多（特定数据库版本、系统库、编译工具） | 一个纯脚本/纯前端小项目 |
| 多人协作，环境必须一致 | 单人项目且本机已就绪 |
| 本机环境被搞脏、难清理 | 团队不熟容器（学习成本 > 收益） |

代价：体积、性能、调试多一层、镜像维护。**它是手段，不是标准动作。**

## 五、跨平台陷阱（"我电脑上能跑"的常见来源）

| 陷阱 | 表现 | 对策 |
|---|---|---|
| 路径分隔符 | Windows 用 `\`，Unix 用 `/` | 用标准库拼路径，别手写 |
| 大小写敏感 | macOS/Windows 不敏感，Linux 敏感 | 导入/文件名大小写必须完全一致 |
| 行尾符 | CRLF vs LF 导致 diff 乱、脚本报错 | 统一行尾符并写进配置 |
| 编码 | 非 UTF-8 导致中文乱码 | 全仓库统一 UTF-8（含输出与日志） |
| 依赖全局安装的包 | 别人机器上没有 | 依赖写进项目清单 |
| 依赖本机命令 | 换机器就缺 | 用跨平台库或在 README 写明前置需求 |
| 时区与区域设置 | 日期解析/数字格式不一致 | 用标准 API，测试里固定时区 |

## 六、验证方法（别只在自己机器上试）

1. **把仓库 clone 到另一个目录**（或新建一个系统用户），完全照 README 走一遍。
2. 故意**删掉/改错一个必需环境变量**，确认启动时报错清楚（而不是运行到一半崩）。
3. 在一台没装过本项目依赖的机器（或干净容器）上再走一遍。
4. 记录"实际用到的命令"和 README 是否一致——**README 与真实步骤不一致就是 bug**。

## 七、与 AI 协作的关系（这点很关键）

环境可复现 = **AI 说的"我这跑通了"变成可验证的**。
否则你只能听它说"应该没问题"——而"在它那边能跑"和"在你这里能跑"是两件事。

配套要求：
- 让它**贴出实际命令与输出**（见 `ai-code-acceptance.md`）。
- 它新增依赖时，必须说明装什么、为什么、以及在你的环境里怎么装。
- 它改动启动方式或环境变量时，**必须同步更新 README 与 `.env.example`**。
